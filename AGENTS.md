# AGENTS.md

Guidance for coding agents working in this repository. Read this before
changing code. It records the behaviors and constraints that matter for
continuing work on the app.

## What this is

An Alfred-inspired local pennyworth for macOS ("Pennyworth", working name:
"Pennyworth"). It searches applications and files, opens web searches,
evaluates calculations, and runs three fixed system commands. The core
app is implemented and committed; the remaining validation items are
listed at the end of this file.

Three hard product constraints:

- No account, no telemetry, no paid Apple Developer membership.
- No direct network requests. Web actions hand the query to the displayed
  site through the default browser (`NSWorkspace.open`).
- No deferred privacy permissions. The app must not request
  Accessibility, Input Monitoring, Contacts, Automation, Screen
  Recording, or Full Disk Access.

## Toolchain and build

- Xcode 26.6, Swift 6.3.3, macOS 26 as minimum target, Apple silicon.
- Strict concurrency enabled everywhere; first-party warnings are errors.
- The Xcode project is generated by xcodegen from `project.yml`. After
  adding or removing files, regenerate it.
- The only dependency is `KeyboardShortcuts`, pinned to **1.10.0**.
  Do not "upgrade" it: the 3.0.1 tag does not exist upstream.

Commands:

```sh
xcodegen generate
xcodebuild -project Pennyworth.xcodeproj -scheme Pennyworth -destination 'platform=macOS' test
xcodebuild -project Pennyworth.xcodeproj -scheme Pennyworth -configuration Release -destination 'platform=macOS' build
```

`xcodebuild test` runs the unit tests only. `PennyworthUITests` is excluded
from the default test scheme because ad hoc signing ("Sign to Run
Locally") breaks the UI test runner bundle; keep it that way.

Local install for verification:

```sh
tmp="$(find "$HOME/Library/Developer/Xcode/DerivedData" \
  -path '*/Build/Products/Release/Pennyworth.app' -print -quit)"
rm -rf "$HOME/Applications/Pennyworth.app" && cp -R "$tmp" "$HOME/Applications/"
open "$HOME/Applications/Pennyworth.app"
```

The app is ad hoc signed (no team). Hashes: install replaces the bundle,
so check SMAppService registration in Settings after each reinstall.

## Architecture

AppKit app with SwiftUI for settings. No storyboard, no SwiftUI app
shell.

```
Pennyworth/App/              lifecycle, AppController wiring, status item
Pennyworth/PennyworthPanel/    panel, results, actions, Quick Look
Pennyworth/Search/           query parsing, coordinator, ranking
Pennyworth/Providers/        application, file, web, calculator, command
Pennyworth/Actions/          action executor and catalog
Pennyworth/Persistence/      SQLite store, settings, web search registry
Pennyworth/Infrastructure/   hotkey, login item, icons, signposts
Pennyworth/Settings/         SwiftUI settings windows
PennyworthTests/             unit tests, judged corpus, regression tests
PennyworthUITests/           UI smoke target (not in test scheme)
```

### Entry point

Do not convert `PennyworthMain.main()` back to `@main` on the AppDelegate.
`@main` on `NSApplicationDelegate` does not wire the delegate without a
storyboard. The app uses an explicit `Pennyworth/App/Main.swift` that does
`NSApplication.shared`, assigns the delegate, and runs.

### Wiring that has broken before

- `SearchCoordinator.onResults` must be assigned in AppController. When it
  went unassigned, queries computed but nothing reached the panel. Keep the
  coordinator callback test green.
- `applicationIndex.onCatalogChange` is currently unused; the coordinator
  does not requery when the catalog changes. Do not connect it without a
  debounce, or Spotlight updates will flood searches.
- The settings window opens via `--open-settings` launch argument; the
  panel can be forced open with `PENNYWORTH_SMOKE_PANEL=1`. Both exist for
  environments where hotkey and menu bar access are unavailable.

## Behavior landmines

### File search runs on a dedicated thread

`FileMetadataService.start`/`stop`/`snapshot` forward to
`MetadataQueryHost`, which owns an NSMetadataQuery on its own thread with
its own run loop. Keep it there: `NSMetadataQuery` can throw or stall
indefinitely on a broken Spotlight config, and running it on the main
actor freezes the panel.

Two indexed rules:

1. Never wrap a single subpredicate in an `AND` compound.
   `NSMetadataQuery` throws `NSInvalidArgumentException` when
   `setSearchScopes:` receives `NSAndPredicateType` with one
   subpredicate. `MetadataQueryHost.buildPredicate` returns the OR
   compound directly for one term and only ANDs across terms.
2. `stop()` and `start()` call the query thread for every poll, so keep
   the poll loop's wakes cheap (it already sleeps ~55 ms between snapshots).

### Identity semantics

- File candidate/entity identity is `volume UUID + document id` (durable
  across renames), falling back to the standardized path.
  `URLResourceValues.documentID` is nil on macOS; the durable id comes
  from the Spotlight attribute `kMDItemDocumentIdentifier`. Do not use
  `fileResourceIdentifier` (it is not durable across restarts).
- The screen saver command's fallback bundle id is
  `com.apple.ScreenSaver.Engine`, not `com.apple.screensaver`.
- Selection events: recorded only for allowed actions, not url or
  calculation rows; deduped within the same row/query/action for 1.5 s.
- A 28-day window applies to learned ranking with per-event exponential
  decay; resets clear the table.

### Key handling and concurrency

- The panel's local key monitor is non-isolated AppKit callbacks. The
  handler extracts only Sendable components (keyCode + modifier flags)
  before crossing into `MainActor.assumeIsolated`. Do not pass `NSEvent`
  into the isolated closure; the compiler rejects it under Swift 6
  `assumeIsolated`'s `@Sending` closure.
- NSStatusBar: The status item looks correct on macOS 26, but on this dev
  box Bartender 6 moved the item to "Always Hidden" in its layout editor,
  and the item's icon was visually identical to the Spotlight magnifier.
  A purple rounded-square glyph is used. When the user reports a missing
  menu bar icon, first check Bartender's layout section, not the code.
- The panel's icon sits in `StatusItemController.makeStatusIcon`.

### Environment notes specific to the dev machine

- This boot volume does not ship Safari (`/System/Applications/Safari.app`
  does not exist). Do not use "safari" in tests. Use TextEdit
  or System Settings instead.
- Spotlight works (mdfind returns results). File search in the app was
  failing because of predicate shape, not the index.
- Window server probes: a running peer status item won't show in
  CGWindowList on this OS (hosted by a system process), so window-list
  checks cannot validate status-bar presence.

## Coding conventions

Follow the repo and global AGENTS rules: strict concurrency, warnings-as
error checks in all targets, no comments unless asked, smallest change,
no new abstractions, no tests unless they verify behavior and regression checks or fix
regressions. "Pennyworth" is the working name and `com.local.pennyworth` is
the working bundle id. They are not permanent: choose an original product name before the
bundle id is locked. Commit with
conventional commits, lowercase subject.

After UI-affecting changes: regenerate the project, run 74 unit tests,
build Release, reinstall into `~/Applications`, and let the user verify
interactively. The tests and a clean Release build are the ground truth
in automation; the panel, menu bar, and shortcut need a live check by
the user.

## Outstanding human validation gates

None of these are fixable by an agent; they are for live use:

- Physical hotkey press across apps (Option+Space may conflict if the
  system owns it; record a new chord in Settings).
- SMAppService login-item registration after a reboot (enable Launch at
  Login, reboot).
- VoiceOver full-flow check.
- Latency budgets: hotkey-to-visible p95, warm file-query first batch.
- One week daily use without a release-blocking failure.
